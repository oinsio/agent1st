## 1) Определение

> **Качественная поставка ПО это код вместе с доказательствами, по которым человек, не писавший код и не видевший его автора, может убедиться в пяти утверждениях: оно делает согласованное; оно не причиняет неожиданного вреда, когда ломается; его можно передать и менять без участия авторов; оно наблюдаемо переживает реальную эксплуатацию; оно не создаёт юридических и security-рисков владельцу. Доказательства должны производить свой эффект, быть видны тому, кто принимает поставку, и собраны до того, как изменение достигнет пользователя.**

Четыре следствия:

1. **Объект определения поставка, а не код.** Код, доказательства о нём и среда, в которой он сделан. curl и SQLite держат часть доказательств в головах авторов с двадцатилетним контекстом. В ИИ-разработке автора завтра нет: сессия закрыта, контекст испарился. Определение написано для этой ситуации.
2. **Качество доказывается артефактами, а не словами, и артефакт засчитывается только по эффекту.** Отчёт агента о прогоне не артефакт. Файл `SECURITY.md` с шаблонным текстом не артефакт. Правило в прозе инструкции не артефакт, если его не проверяет инструмент. (v1.1: добавлено по flutter_agent_harness и herdr.)
3. **Определение задаёт необходимое, не достаточное.** Поставка, собравшая все артефакты, может быть медленной, неудобной и утекать персональными данными. Производительность, пригодность к использованию и приватность вне определения.
4. **Планка едина, доказательства дифференцированы.** Ядро и компенсация обязательны для всего кода. Надстройка включается по риску. Снижать уровень компонента можно только через доказанную границу, иначе у обоих уровень худшего.

## 2) Пять свойств

| Свойство | Короткая формула |
|---|---|
| **А. Соответствие** | делает согласованное, и это проверяемо |
| **Б. Безвредность** | ломается предсказуемо и видимо; не теряет данные и деньги неожиданно |
| **В. Передаваемость** | чужой человек или свежий агент поднимает, понимает и меняет по репозиторию |
| **Г. Эксплуатируемость** | в проде видно, что происходит, и можно откатить |
| **Д. Чистота** | не создаёт рисков владельцу: секреты, зависимости, лицензии, уязвимости |

## 3) Как устроен критерий

Каждый критерий записан через **эффект**, а не через конкретный артефакт. Поля:

- **Эффект:** что наблюдаемо верно.
- **Артефакт по умолчанию:** чем это обычно доказывают. Засчитывается только если производит эффект: пустой шаблон, незаполненный файл и правило без проверки не засчитываются (v1.1). Инструкция для оператора засчитывается только отрепетированной: процедура, которую никто не прогонял, равна шаблону (v1.2). Проверка, которую можно пропустить одной переменной окружения или одной машиной, не является проверкой (v1.2). Чекбокс шаблона равен правилу в прозе: засчитывается, если его состояние проверяет обвязка перед переходом статуса (v1.3: GitLab, «dry-run проведён» отмечен в 7 изменениях из 20 со статусом «complete»).
- **Замены:** что ещё принимается. Артефакт вне репозитория засчитывается, если он публично доступен и на него указано из репозитория. Приватный артефакт засчитывается только для профиля «доказано себе» (§8). Приватный прогон репетиции засчитывается и для продуктового профиля, если публичны его правило-сторож, частота и код проверки (v1.3, GitLab).
- **Когда:** до доставки изменения пользователю. Каденция «на каждый push» не требуется.
- **Происхождение:** Я (ядро, подтверждено curl и SQLite), К (компенсация, обязано называть риск ИИ, который закрывает).

Правило включения в обязательный набор: **без этого критерия дефект доходит до пользователя незамеченным, и цена проверки ниже цены дефекта.** Цену проверки нужно измерять: Gnomish Factory записал 1 ч 24 мин на один полный прогон и ввёл правило объёма проверки по задаче; flutter_agent_harness держит бюджеты длительности тестов храповиком. Аппарат доказательств может стать дороже продукта, и определение этого не запрещает, но требует, чтобы цена была видна (v1.1).

## 7) Среда агента: условия, при которых доказательства возможны

Это не критерии ПО. Без них агент может подменить артефакт, и §4–§6 не доказывают ничего. Отрицательный контроль показал, что четыре из пяти разрушительных инцидентов произошли здесь; Clear Progress воспроизвёл предусловие PocketOS без инцидента; fah показал предельный случай, где агент правит свои правила, а сливает машина.

| Код | Условие | Артефакты по умолчанию (v1.1) |
|---|---|---|
| С1 | Из среды агента недостижимы прод и его учётные данные | секреты вне рабочей директории; «тестовые процессы никогда не наследуют окружение оператора» |
| С2 | Разрушительные команды проходят подтверждение или dry-run независимо от режима инструмента | deny-список в конфигурации агента, не в прозе |
| С3 | Бэкапы лежат вне зоны поражения агента, восстановление отрепетировано | |
| С4 | Права токенов агента минимальны для задачи | агент под собственной учётной записью с объявленными скоупами |
| С5 | Проверяющие артефакты защищены от правки в том же шаге, что и код (см. К2) | «агент никогда не коммитит»; список защищённых путей; запечатанная копия |
| С6 | Инструменты агента прибиты по версии и проверены как зависимости (см. Я15) | шаги обвязки и образы прибиты по хэшу (v1.3: было «actions по хэшу»); цикл самого агента не берётся «всегда последним» |

## 8) Профили доказательств: кому доказано

| Тип | Кому видны артефакты | Что значит «принято» |
|---|---|---|
| Заказная | заказчику, как часть акта приёмки | пять свойств это разделы акта; свойство без артефактов не принято |
| Продуктовая | владельцу продукта | релиз не выходит без прогона §4–§5; список незакрытого публичен. v1.3: артефакты Г это статус, трекер инцидентов, разборы с корректирующими действиями, политика бэкапов с частотой и сторожем, журнал изменений со статусами; прогон репетиции может быть приватен при публичном стороже (GitLab) |
| Библиотечная | публике; репозиторий и есть доказательство | артефакты в репозитории или публично по ссылке из него; приватные не засчитываются |
| Самостоятельный хостинг (v1.1) | владельцу кода и пользователю-хостеру | эксплуатация и бэкап уходят к пользователю, поэтому артефакты Г это инструменты и инструкции ему: экспорт, проверка восстановления, список того, что сломается при обновлении схемы (Clear Progress); инструкции засчитываются отрепетированными (v1.2) |

Если одна поставка обслуживает несколько профилей, профили перечислены, для каждого указано, где лежат его артефакты, и видимый из репозитория набор закрывает самый публичный из профилей; продуктовый профиль закрывается перед владельцем продукта отдельно (v1.2, Documenso: Cloud и самостоятельный хостинг из одного репозитория).

## 9) Как пользоваться

1. Для продукта: пять свойств как разделы приёмки по профилю §8.
2. Для компонента: квадрант по обратимости и адресату, затем тип компонента, затем Н19, затем набор надстройки.
3. Для изменения: ядро и компенсация до доставки; надстройка по худшему из уровня компонента и уровня изменения.
4. Для среды: §7 проверяется при настройке и при каждом расширении прав агента.
5. Для команды из одного человека и агентов или без человека-читателя: Н7 обязателен, К8 закрывается воротами мутаций, К1 закрывается обвязкой, а не отчётом (v1.1).
6. Для спора «качественно или нет»: вопрос переформулируется в «какого артефакта не хватает, кому он должен быть виден и производит ли он эффект».

## 10) Что не закрыто

- **Пороги** для К4, К8, Н1, Н8, Н9. Калибруются на реальных проектах.
- **Доказанная граница** для Н19 без аппаратной изоляции.
- **Свойство Г откалибровано по обоим профилям** (v1.3): хостерский на Documenso, продуктовый на GitLab.com. Артефакты оператора не приватны по природе, приватен только прогон. Открыто: частота репетиций не задана; Н12 для выкатки без отката закрыт заменой «ступенями», её порог не калибровался.
- **Объявленная тихая деградация.** Достаточно ли объявления без следа для best-effort шагов, чей отказ не меняет результат (Я5, GitLab).
- **Нагрузка от собственных автоматов** (Н3, Н4) не калибровалась.
- **Стоимость повторов.** Правило Я5 о видимых повторах не задаёт порог; он калибруется как пороги К4 и К8.
- **Стоимость доказательств.** Определение требует видеть цену, но не задаёт потолок. Кандидат: бюджеты длительности проверок как храповик.
- **Производительность вне объёма.** herdr показал дешёвый артефакт: изменение в горячем пути сопровождается замером с дельтой масштабирования. Это требование к доказательству, не к скорости; включать ли, решает сопровождающий.
- **Гипотезы о поведении моделей** (К3, К4, К5) подтверждены наблюдениями на четырёх ИИ-проектах, но не исследованиями на агентах.
