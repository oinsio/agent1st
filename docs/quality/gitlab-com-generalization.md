# Фильтр от стека: находки GitLab.com

**Статус:** записано 2026-10-19 по `calibration-gitlab-com.md`. Тот же фильтр, что в `documenso-generalization.md`: три условия, находка проходит в определение только целиком.

1. Класс дефекта не зависит от языка и платформы.
2. Проверка сформулирована через наблюдаемый эффект, не через имя инструмента.
3. На другом стеке меняется только инструмент, не критерий.

Четвёртое условие этой пробы: оператор с сотнями инженеров. Для каждой находки записано, что остаётся, если команда это один человек и агенты, а инструменты это cron, один файл и трекер.

## 2) Что отфильтровано

- Названия инструментов (Snitch, Mimir, incident.io, Helm, jsonnet) остаются примерами в примечаниях.
- Квартальная частота учебных аварий и ротация команд: масштаб оператора. Общее требование: репетиция людьми существует и записывает измерения; частоту задаёт сопровождающий.
- Модель зрелости из трёх уровней: конкретная шкала GitLab. Общее: минимальный уровень наблюдаемости как ворота обвязки.
- `.gitignore` с принудительно добавленными файлами: особенность git, не класс дефекта.
- Семантика метки `automation:ml`: не расшифрована, не используется.

## 3) Что идёт в v1.3

Правки по существу: Н6 (сторож и измерения), Н12 (триггер отката; замена «ступенями»), Н13 (каталог как замена), Н15 (незакрытое как фильтр трекера), §3 (чекбокс; приватный прогон с публичным сторожем), §8 (артефакты продуктового профиля Г).
Правки формы: Я12 (статус фильтруемый), Я10 (сгенерированное сверяется), К7 (учёт на уровне изменения), Я5 и Н4 (примечания), §10 (Г откалибровано; два новых вопроса).

## 4) Проверка переноса на одного человека и агентов

| Находка | Что остаётся при cron, одном файле и трекере |
|---|---|
| 1 сторож | cron-задача восстановления + пинг в любой сторож; одна строка |
| 2 триггер отката | два поля в шаблоне PR: метрика-порог и время отката |
| 3 ступени | два окружения и smoke между ними; откат ступени делает инструмент выкатки |
| 4 чекбокс | задача CI читает тело PR и валит при неотмеченном пункте |
| 5 статус | метка или поле фронтматтера |
| 6 каталог | один файл со списком компонентов и линтер |
| 7 незакрытое | метка «corrective action» и сохранённый фильтр |
| 8 приватный прогон | ссылка на правило-сторожа из README |
| 16 измерения | таблица «дата, сценарий, длительность, ссылка» |
