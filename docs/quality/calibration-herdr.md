# Калибровка определения v1 на herdr

**Статус:** шестая проба, третья по версии 1 (`definition.md`, коды Я/К/Н/С) и первая независимая: проект чужих разработчиков, написанный с ИИ. herdr это терминальный runtime для кодирующих агентов: TUI-мультиплексор с сервером, удалёнными машинами по SSH и детекцией состояния агентов по экрану. Rust, один вендоренный C-крейт. Без внешнего признания как эталона, но с реальными пользователями и релизным циклом.

**Источник фактов:** клон `github.com/herdrdev/herdr`, коммит `143bf5fd` (2026-10-16), полная история: 1865 коммитов с 2026-03-23, десять и более авторов, два бот-аккаунта агентов (`akbash-bot`, `kangal-bot`). Объём: 268 976 строк Rust в `src` и `crates`, 22 505 в `tests`, 4292 теста, 99 тегов релизов, последний v0.9.5 это hotfix к v0.9.4 через день.

**Политика ИИ проекта** (`CONTRIBUTING.md`, раздел «The problem is whose agent»): «агенты пишут большую часть сегодняшнего кода, включая наш; мы контролируем модель, инструкции, контекст и инструменты своих агентов; чужих не можем, поэтому непрошеные PR закрываются автоматически». Агенты сопровождающих коммитят под отдельными бот-аккаунтами; строки `Co-authored-by` с ИИ запрещены.

**Квадрант:** внешний адресат, релиз обратим через каналы stable/preview, хранит сессии пользователей, парсит недоверенный ввод (байты терминала, экраны агентов, stdin хуков). LLM не вызывает.

Шкала: ДА / ЧАСТИЧНО / НЕТ / Н/П.

## 5) Что это говорит об определении

1. **Независимая проба подтверждает различающую способность.** herdr между Clear Progress и Gnomish Factory по ядру (11 ДА против 8 и 17), с собственным профилем: сильны совместимость, документация, цепочка поставок и дисциплина релизов; слабы сканирование, покрытие и запись решений. Определение видит профиль, а не одно число.
2. **К7 нужен четвёртый вариант: контроль.** Три записанных (учёт модели, запрет ИИ-кода, раскрытие при вкладе) не описывают herdr. Их политика: принимается код только от агентов, которыми управляет сопровождающий; внешние агенты не допускаются; агенты имеют собственные учётные записи. Это происхождение через контроль над автором, а не через метаданные коммита.
3. **Я5 реализовался во втором ИИ-проекте подряд.** #5310 в herdr и #97 в Clear Progress это один класс: широкий обработчик выдаёт любую ошибку за одно конкретное условие. В обоих случаях правило существовало прозой и не было включено как lint. Вывод для Я5: артефакт по умолчанию это именно линтер, проза не считается.
4. **К2 получил ещё два дешёвых артефакта.** Запрет менять замороженные фикстуры «чтобы благословить изменение» и pre-commit, запирающий файл на релизные коммиты. Вместе с механизмами Gnomish Factory у К2 теперь шесть кандидатов в артефакты по умолчанию.
5. **Я1 должен явно принимать трассировку через трекер.** Коммит с `refs #issue` и курируемый по ссылкам changelog дают ту же связь «что просили → что проверили», что идентификаторы требований. Записать как замену.
6. **Я16 поймал реальный риск.** 944 `unsafe` вокруг FFI эмулятора терминала без miri и санитайзеров. Для Rust «динамические проверки памяти» не пусты.
7. **Я19 провален в пяти из шести проб, Я20 в шести из шести.** Я19 остаётся: канал приёма уязвимостей стоит один файл, и его отсутствие у проекта с удалённым доступом по SSH это дефект. Я20 в ядре не держится. По решению сопровождающего исследования послужной список в критерии не идёт; остаётся вариант перенести Я20 в надстройку для профиля с релизным циклом или снять. Решение за сопровождающим.
8. **Я12 допускает решения вне репозитория, и это слабость для передачи.** PRD в игнорируемом `.local/prd/`. Правила в `AGENTS.md` говорят «что», не «почему не иначе». Формулировка «доступны из репозитория» корректно даёт ЧАСТИЧНО, а не НЕТ, и это верный вердикт: передача состоялась, но через людей.
9. **Производительность как артефакт, не как свойство.** Определение исключает производительность из объёма (§1.3). herdr показывает дешёвый артефакт: «изменение в горячем пути сопровождается замером с дельтой масштабирования». Это не требование к скорости, а требование к доказательству. Кандидат в надстройку, если сопровождающий сочтёт нужным расширить объём.

## 6) Ограничения

- Прогоны не запускались; счёт `unwrap()` приближённый, потому что тесты в Rust живут в тех же файлах.
- Приватные ревью Greptile и CodeRabbit не видны; К8 и Н7 оценены по описанию процесса.
- Один независимый проект. Для вывода «определение переносимо» нужен хотя бы ещё один, другого стека и другого типа: веб-сервис.
