# Логическое ревью определения v2.3 по методике logika

**Дата:** 2026-10-19. **Объект:** `definition.md` версии 2.3. **Метод:** режим «Ревью» скилла [evilfreelancer/logika](https://github.com/evilfreelancer/logika): классическая формальная логика по Челпанову. Текст не переписывается; для каждой ошибки названы место, русское и латинское имя, причина и способ исправления. Формальная истинность (вывод следует из посылок) и материальная истинность (посылки верны) проверены раздельно и в таблице различены.

Это разбор, а не правка. Правки, если сопровождающий их примет, пойдут в v2.4 по обычному паттерну версий.

---

## Вердикт

**Найдено 18 ошибок: 6 критичных, 12 спорных.** Критичная по logika: вывод не следует из посылок или посылка подменяется. Спорная: вывод возможен, но обоснован недостаточно.

Главная линия: документ объявляет один принцип вердикта («по эффекту, видимому принимающему») и одну область («нет критериев, выполнимых только после истории эксплуатации»), а затем сам отступает от обоих в нескольких местах. Ни одна из ошибок не ломает определение целиком; все устранимы локальными правками формулировок.

## Структура аргументации

**Тезис.** Качественная поставка это код вместе с доказательствами, по которым чужой читатель убеждается в пяти утверждениях (А–Д); доказательства производят эффект, видны принимающему и собраны до доставки.

**Посылки.** (1) В ИИ-разработке автор исчезает вместе с контекстом, поэтому доказательства не могут жить в головах. (2) Сопровождение дороже разработки и состоит в основном из доработок, поэтому передаваемость важнее эксплуатируемости. (3) Агент может подменить артефакт, поэтому нужны среда (§7) и правила зачёта (§3). (4) Риски различаются по компонентам, поэтому набор доказательств дифференцирован.

**Как выводится.** Из тезиса объявлены четыре «следствия» (§1), из них выведена форма критерия «эффект, не артефакт» (§3) и шкала вердиктов; далее критерии разложены по ярусам Я/К/Н/С и профилям «кому доказано» (§8). Материальная истинность посылок (1) и (3) опирается на инциденты и калибровки (`definition-evidence.md`), посылки (2) на литературу без ссылки.

## Скрытые посылки

Невысказанные посылки, без которых выводы документа не работают, и степень их спорности:

1. **Из вердиктов по критериям выводится вердикт по пяти утверждениям.** Определение обещает убедиться «в пяти утверждениях», шкала §3 ставит вердикт на критерий. Правило свёртки (достаточно ли одного НЕТ в ядре, чтобы свойство не доказано; как ЧАСТИЧНО по Я5 влияет на Б) записано только для заказного профиля («свойство без артефактов не принято»). Для остальных профилей свёртка отсутствует. Спорна.
2. **Принимающий поставку и есть «человек, не видевший автора».** §8 называет принимающих (заказчик, владелец продукта, публика, хостер); владелец продукта автора обычно видел. Если принимающий знает автора, принцип «видно принимающему» и условие определения «не видевший автора» расходятся. Спорна слабо.
3. **Тесты для нового кода приходят отдельной попыткой.** К2 запрещает менять проверяющие артефакты в одной попытке с кодом; Я1 и К8 требуют тесты, привязанные к критерию. Совместимо только если агент пишет тесты отдельной попыткой через владельца пути (С5). Это не сказано; без этой посылки К2 и К8 противоречат. Спорна.
4. **Цена дефекта известна** (правило 6, п.3 таблицы). Нигде не измеряется.
5. **Профили упорядочены по публичности** (§8, п.6 таблицы).
6. **Уровень изменения определим** (п.13 таблицы).
7. **Статистика сопровождения переносится на ИИ-разработку** (п.18).
8. **Обвязка, «не подчинённая автору изменения» (Я7), существует и для человеческого кода.** Я7 в ядре для всего кода, но его эффект дублирует половину К1 (компенсация для кода агента). Если Я7 верен для всего кода, К1 добавляет только «отчёт агента не засчитывается» и «привязка к дереву». Не ошибка, но дубль между ярусами, который статус объявил снятым.
