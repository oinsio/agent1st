# Прогон v2.1 по девяти калибровкам

**Статус:** записано 2026-10-19. К фактам девяти калибровок и прогона кандидатов (`rerun-candidates.md`) применены правила `definition.md` версии 2.1. Факты не пересобирались: клоны не перечитывались, прогоны не запускались. Где новое правило требует факта, которого нет ни в калибровке, ни в отчётах агентов, стоит пометка «нужен факт».

**Что проверяется.** Три группы правок: новые критерии Н20–Н27 и ось «под нагрузкой»; правило 7 §3 и уточнение правила 2; уточнения Я4, Я10, Я13, Я17, Я21, Н2, Н3, Н4, Н11, Н15, Н16, Н17. Для каждого проекта сначала записана строка «не подключено к обвязке» по §9 п. 8, затем вердикты по новым критериям, затем смены вердиктов существующих критериев относительно `rerun-v1.3.md`. Строки без смен не перечислены.

Обозначения: «→» смена вердикта; «(п. 7)» правило 7 §3; «(ут.)» уточнение критерия в v2.1.

### 10.3 Наблюдения

1. **Формулировка через эффект работает там, где старая давала Н/П.** herdr Н24 и Н25 с Н/П на ДА, curl Н25 ДА, GF Н23, Н24, Н25 ДА. Три проекта без веб-аутентификации получили содержательные вердикты по безопасности, которых кандидаты из сверки с OWASP дать не могли.
2. **Н27 различает.** Единственное ДА у GF с гейтом связности, у остальных ЧАСТИЧНО или НЕТ по разным причинам: приватный инструмент (SQLite), реестр без связи (curl), сертификация вместо проверки (Doc, GL), идентификаторы без реестра (fah). Критерий видит профиль, не одно число.
3. **Н21 пока не различает.** У всех пяти проектов с интерфейсом ЧАСТИЧНО, и причина у всех одна: сценарии идут по фикстурам или не подключены к обвязке. Единственный сценарий по тексту для пользователя у Clear Progress не в CI. Для калибровки Н21 нужен проект с e2e по документации в обвязке; в наборе такого нет.
4. **Н20 держится на разных артефактах в разных типах.** ДА у GL (число запросов и планы) и у приложения fah (размер); ЧАСТИЧНО у библиотек и CLI из-за ручных гейтов; НЕТ у Doc, где ось нагрузки выполнена, а артефакта нет. Условие v2.1 перевело GF из Н/П в НЕТ: это ожидаемый эффект расширенного условия, и его стоит проверить ещё на одном оркестраторе.
5. **Строка «не подключено к обвязке» оправдала себя.** У Clear Progress один факт ограничивает шесть вердиктов, у Documenso пять фактов ограничивают четыре критерия и подпункт Н25, у fah два факта разводят вердикты CLI и приложения. Без строки эти факты повторялись бы в каждой ячейке.
6. **Уточнение Я10 снизило лучший по этому критерию ИИ-проект.** Руководства GF трассированы к требованиям, но не исполняются. Либо «исполняема обвязкой» слишком сильно для руководств оператора и достаточно трассировки, либо GF действительно недостаёт исполнения. Решение в §7.
7. **Сводка прогона кандидатов содержала ошибку.** Тест на отсутствие токена в логах есть у GF и был пропущен; §10 определения и `changes-v2.1.md` поправлены, в `rerun-candidates.md` оставлена пометка.
