# Калибровка определения v1 на flutter_agent_harness

**Статус:** седьмая проба, четвёртая по версии 1 (`definition.md`, коды Я/К/Н/С). Первый проект, который пишется ИИ-агентами почти полностью: из последних 100 коммитов 62 принадлежат аккаунту «AI Teammate», ещё 29 второму машинному аккаунту, 6 человеку. PR агента сливает машина по зелёному CI. Ядро оценивается по 20 пунктам: Я20 удалён решением сопровождающего исследования 2026-10-19.

**Что это:** `fa`, кроссплатформенный агентский harness на Dart: CLI и TUI, Flutter-приложение, браузерное расширение, Outlook-add-in, хаб обмена сообщениями между агентами, бенчмарки Terminal-Bench. Создан 2026-07-13, 77 звёзд, MIT.

**Источник фактов:** клон последнего коммита `main` (`94e2707`, 2026-10-18) без истории, 327 МБ рабочего дерева из-за wasm-бинарников и аудио; полный клон превысил 1,2 ГБ и был прерван. Авторство и PR взяты через GitHub API. Объём: 228 779 строк Dart в `lib`, `packages`, `sdk`; 330 887 строк тестов (1,45:1); 17 391 тест; 28 workflows; 89 скриптов; `AGENTS.md` на 2124 строки и 17 281 слово.

**Квадрант:** внешний адресат (pub.dev, магазины приложений), релиз обратим, хранит сессии и секреты пользователя, вызывает LLM, выполняет недоверенный ввод. Надстройка обязательна целиком, Н17 центральна.

Шкала: ДА / ЧАСТИЧНО / НЕТ / Н/П.

## 5) Что это говорит об определении

1. **Полностью агентная разработка держится на одном столпе: целостности CI.** Когда человек вышел из цикла, К1 остаётся единственным доказательством, и проект это понимает: валидация точного дерева, сторож слияния, запрет фикстурам притворяться прогонами, манифест шардов. При этом К2 и С5 отсутствуют целиком: агент правит тесты, CI и собственные инструкции, а сливает машина. Вся конструкция держится на предположении, что агент не оптимизирует ворота. Собственный скилл проекта описывает «ворота, маскирующие друг друга» как класс инцидентов. Определение правильно требует К2 и С5 в обязательном наборе; этот проект показывает цену их отсутствия в предельном случае.
2. **Пустой артефакт.** `SECURITY.md` с шаблонным текстом формально закрывает Я19. Колонка «артефакт по умолчанию» должна читаться через эффект: есть рабочий канал и срок реакции. Это общее правило для всех пунктов: наличие файла не засчитывается, пока он не делает то, ради чего нужен.
3. **К5 нарушен ровно так, как предсказывает Agent1st.** 17 тысяч слов инструкций, написанных агентами для агентов, с правилом «no essays» в первой строке. Проект ограничил размер файлов кода и не ограничил размер правил. К5 нужен измеримый артефакт: потолок объёма инструкций и привязка к путям.
4. **Я7 получил артефакт по умолчанию:** манифест шардов с проверкой объединения и непересечения. Это и есть «нельзя прогнать часть и назвать целым» в виде проверки.
5. **К4 автоматизируем дёшево.** Ворота дублирования с храповиком работают на 228 тысячах строк. Сомнение из калибровок curl и SQLite снято для ИИ-проектов: там дубли реализовались, здесь их ловят.
6. **CRAP как объединённый артефакт для Н8 и Н9.** Сложность, умноженная на непокрытость, с пином худшего значения даёт один храповик вместо двух порогов.
7. **Н7 получил отрицательный пример.** Нет второго читателя вообще. Для полностью агентной разработки Н7 должен читаться как «второй агент другой модели без доступа к рассуждениям первого», и это обязательно, а не по риску.
8. **Аппарат проверки может превышать продукт.** 28 workflows, CI каждые два часа, машина состояний каждые десять минут, 89 скриптов, 1,2 ГБ истории. Определение не ограничивает стоимость доказательств. Для создания качественного ПО это не критерий, но §10 должен признать: правило «цена проверки ниже цены дефекта» нуждается в измерении, и этот проект измеряет бюджеты длительности тестов храповиком.

## 6) Ограничения

- История не клонирована: Я14 по истории не проверялся, авторство по 100 последним коммитам через API.
- Механизм метки `pr_approved` и защита ветки живут вне репозитория и не видны.
- Прогоны не запускались.
- Проект сам есть агентский harness, как и Gnomish Factory; сильный Н17 отчасти следствие предмета.
