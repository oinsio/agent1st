# К4 «воспроизведение соседнего кода»: эффект измеряет не тот вред

**Задача:** критически разобрать К4 из `definition.md` версии 2.1: риск «воспроизведение соседнего кода», эффект «нет необъявленных дублей выше порога», артефакты «ворота дублирования с храповиком на файл и между модулями; объявленные пары с маркерами синхронизации и правилом трёх; дублирование разрешено, если объявлено». `definition.md` не меняется: выводы записаны кандидатами в правку следующей версии и поправкой к одному вердикту калибровки.

**Метод.** Эффект сверен с вредом, который риск причиняет; каждый артефакт проверен правилами зачёта §3; вердикты К4 во всех девяти калибровках перечитаны на соответствие правилам v2.x.

---

## 1) Итог

Пункт держится, но слабее, чем выглядит. Эффект описывает статическое состояние дерева и пропускает дрейф копий, который и есть цена для В. Разрешение «если объявлено» без проверки синхронности это флаг. «Правило трёх» это эвристика, не артефакт. Единственное ДА с инструментом у одного проекта из девяти; ДА у Gnomish Factory поставлено на основании, не относящемся к К4. Самый яркий инцидент, приписанный К4, доказывает К8 сильнее, чем К4.

## 2) Семь замечаний

### 2.1 Эффект измеряет не тот вред

Вред от копии не в её существовании, а в расхождении: исправление попадает в одну копию и не попадает в другую. Эффект «нет необъявленных дублей выше порога» говорит о состоянии дерева в момент проверки и ничего о расхождении. Объявленная пара допускается, но определение не требует, чтобы расхождение пары что-то ломало. Критерий ловит копирование и пропускает дрейф.

### 2.2 «Разрешено, если объявлено» без проверки это флаг

Объявление стоит одну строку комментария. Если за ним нет проверки синхронности, агент может объявить парой что угодно, и критерий закрывается так же, как правило в прозе. По правилу 1 §3 это не засчитывается, но текст К4 этого не говорит. У К5 тот же вопрос решён строже: «один источник через включение или объявленный дубль», включение предпочтительно. К4 должен брать ту же лестницу: устранение через единый источник, затем объявленная пара с проверкой, и только она засчитывается.

### 2.3 «Правило трёх» не артефакт

Эвристика рефакторинга «третья копия извлекается» стоит в колонке артефактов рядом с воротами, но проверить её нечем. По правилу 1 ей место в пояснении.

### 2.4 Калибровка Gnomish Factory поставила ДА на неверном основании

Запись калибровки: «Инструмента поиска дублей нет, но PIT 100% не даёт дублям жить непокрытыми». Мутационный счёт к К4 не относится: две копии кода с двумя копиями тестов проходят мутации одинаково, и расхождение копий мутации не ловят. Единственный тестовый механизм, относящийся к вреду К4, это проверка расхождения объявленной пары, а у проекта есть правило manual-sync-pairs в прозе и маркеры без проверки. По правилам v2.x это ЧАСТИЧНО.

Сводка вердиктов К4 по девяти калибровкам после поправки:

| Проект | Вердикт | Основание |
|---|---|---|
| curl, SQLite | Н/П | код без ИИ |
| Инциденты | нет инцидента | дубли не фигурируют ни в одном из набора |
| Clear Progress | НЕТ | риск реализовался, инструмента нет |
| Gnomish Factory | ДА → ЧАСТИЧНО | объявленные пары с маркерами, проверки синхронности и детектора нет |
| herdr | ЧАСТИЧНО | «нет god objects» и «переиспользовать паттерны» прозой |
| flutter_agent_harness | ДА | ворота 1% на файл с базой-храповиком, проверка между модулями |
| Documenso | ЧАСТИЧНО | два соседних файла по 825 и 853 строки не объявлены ни дублями, ни раздельными |
| GitLab.com | не калибровался | `CLAUDE.md` как объявленная копия `AGENTS.md` учтена в К5 |

ДА с инструментом у одного проекта из девяти.

### 2.5 Доказательная база риска тонкая

Реализация риска записана у одного проекта, Clear Progress: три репозитория одной формы и четвёртый мёртвый хук. Но вред там назван так: «одинаковые непокрытые ветки» в трёх копиях. Это ловят мутации, то есть К8 и Н1, а не ворота дублирования. Самый яркий инцидент К4 иллюстрирует К8. За К4 остаётся довод от curl и SQLite: без ИИ проекты сопровождаемы без проверки дублей, значит, проверка это компенсация. Довод от отсутствия, не от наблюдённого дефекта. §10 это признаёт в строке о гипотезах К3, К4, К5.

### 2.6 Объём не задан

Клон-детектор на тестах, фикстурах, сгенерированном и вендоренном коде даёт шум. Дубли в тестах часто полезны для читаемости; сгенерированное сверяется с источником по Я10; вендоренное с журналом патчей это Я15. К4 должен назвать исключения, иначе ворота отключат целыми каталогами, и правило 2 сработает против самого критерия.

### 2.7 Порог на файл пропускает системный дубль

Трёхстрочная конструкция, скопированная в пятьдесят файлов, не превышает порог ни в одном файле, а это типичный след модели: один и тот же обработчик, одна и та же проверка. «Между модулями» в тексте есть, порог для дерева в целом не назван. В §10 упомянут один порог К4, нужны два.

## 3) Кандидаты в правки

| Место | Правка |
|---|---|
| К4, эффект | «Копии кода либо ниже порога, либо объявлены парой с проверкой синхронности; расхождение объявленной пары валит сборку. Предпочтительно устранение через единый источник» |
| К4, артефакты | клон-детектор с базой и храповиком, порог отдельно по файлу и по дереву; маркеры пары с проверкой, которая падает при изменении одной стороны без другой; исключения для тестов, сгенерированного и вендоренного записаны в конфигурации детектора, не отключением каталогов. «Правило трёх» в пояснение |
| К4, риск | уточнить: «модель воспроизводит код из контекста вместо вызова существующего; копии затем расходятся» |
| §10 | два порога К4: на файл и на дерево |
| `rerun-v2.1.md` | при следующем прогоне Gnomish Factory К4 ДА → ЧАСТИЧНО по правилу 1; пометка, что инцидент Clear Progress доказывает К8 сильнее, чем К4 |

Что проверить до правки: есть ли у flutter_agent_harness проверка расхождения объявленных пар или только детектор; нужен факт по клону.
